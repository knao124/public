詳細解説一覧

1. 全体像

OpenTelemetry AI Agent Observability: Agent QAの共通土台を作る

この資料は、AI agentの観測をOpenTelemetryで標準化する必要性を説明する導入記事です。LLM呼び出しだけではなく、agent application、agent framework、tools、memory、multi-agent協調まで含む実行を、評価と改善に使えるtraceとして扱う発想が中心です。

学び: 最初に読むべき資料です。以降のPhoenix、LangWatch、AgentEvals、Tracetestはすべて「agentの実行過程をtraceで固定し、それを評価する」という前提に立っています。この前提を把握しないと、個別ツールの違いだけを追ってしまいます。

2. 標準schema

OpenTelemetry GenAI Semantic Conventions: 評価器が読むspan schema

この仕様は、LLM呼び出し、retrieval、tool executionをOpenTelemetry spanとしてどう表現するかを定義します。agent自動QAでは、評価器が読む属性の名前と意味を揃えるための土台になります。

学び: 評価ツールを見る前に読むべき資料です。何をtraceに残すべきかが曖昧なままAgentEvalsやTracetestを入れても、評価器に必要な属性が足りず、最終回答だけの採点に戻ってしまいます。

3. 可視化例

Inside the LLM Call: Agent実行をspan treeとして見る

この公式ブログは、VS Code Copilotなどのagent interactionをOpenTelemetryで可視化し、invoke_agent、chat、execute_toolのようなspan treeとして見る例を示します。仕様を現実の画面とデバッグ手順に接続する資料です。

学び: GenAI semantic conventionsを読んだ直後に読むと、属性名とspan treeが実際の開発体験でどう役立つかが分かります。QA基盤の前に、まずtrace viewerで何を見るべきかを掴めます。

4. 計測層

OpenInference: AIアプリをOTel互換traceにそろえる計測層

OpenInferenceは、LLM、retriever、tool、agent frameworkをOpenTelemetry互換のtraceとして出すための仕様とinstrumentation群です。agent QAでは、評価器に入れる前のセンサー層として重要です。

学び: 自前でspanを全部書く前に読むべき資料です。OpenAI、OpenAI Agents、Claude Agent SDK、LangChain、LlamaIndex、CrewAI、Google ADK、AutoGenなど、既存frameworkからどこまで自動計測できるかを判断できます。

5. 計測層

OpenLLMetry / Traceloop: LLM appをOTel pipelineへ乗せる

OpenLLMetryは、LLM applicationの実行をOpenTelemetry traceとして出すOSS instrumentationです。Tracetest記事の実装例でも使われる、LLM app向けの計測レイヤーです。

学び: OpenInferenceと並べて読むと、AI計測ライブラリの位置づけが分かります。特に既存のOTel collectorやbackendを使い続けながらLLM appを可視化したい場合に参考になります。

6. 実装チュートリアル

Phoenix Tracing Tutorial: Support Agentを部品ごとに評価する

PhoenixのTracing Tutorialは、サポートagentを題材に、LLM call、tool execution、RAG retrieval、session、annotation、LLM-as-Judgeまでを段階的に組み立てる実践教材です。

学び: 計測ライブラリを理解した後、最初に手を動かす資料として最適です。agent QAを最終回答の採点ではなく、分類、検索、tool、生成、sessionの各段階に分ける方法が学べます。

7. 実装チュートリアル

Phoenix + Open Agent Spec: Runtimeを替えても同じ基準で評価する

このブログは、Agent Specで定義したagentをLangGraphとWayFlowなど異なるruntimeで動かし、Phoenixにtraceを送り、同じ評価基準で比較する構成を示します。

学び: Phoenix基礎の次に読む資料です。agent runtimeを変更したり、framework移行を検討したりするとき、最終回答だけでなくtraceとevalで比較する方法が分かります。

8. 評価基盤接続

LangWatch OTel Integration: 既存traceを評価・simulationへ流す

LangWatchのOTel Integration Guideは、任意言語のOpenTelemetry SDKからLangWatchのOTLP endpointへLLM/agent traceを送る方法を示します。

学び: traceを出せるようになった後に読む資料です。計測したデータを評価・simulation・annotationの画面へ接続する方法が分かります。

9. Simulation QA

LangWatch Agent Simulations: Multi-turn QAをscenarioとして書く

LangWatch Agent Simulationsは、unit test、component eval、agent simulationの三層でagentを評価し、multi-turn scenarioで会話、tool call、状態遷移を検査する方法を説明します。

学び: toolやretrievalをtraceできるようになった後に読む資料です。agent QAを単発input-outputから、会話全体の振る舞いへ広げる発想が得られます。

10. Trace assertion

Tracetest Docs: traceをテスト仕様として使う

Tracetestは、OpenTelemetry traceに対してspanの存在、属性、duration、side effectをassertし、E2Eやintegration testを深く検証するツールです。

学び: LLM judgeに頼らず決定的に検査できる領域を理解するために読みます。agentが正しいtoolを呼んだか、禁止された副作用を起こしていないかを見るのに向いています。

11. Trace assertion

Testing LLM Apps with Trace-Based Testing: 外から叩き、内側のtraceを検査する

この記事は、PlaywrightでLLM appを外側から実行し、OpenTelemetry/OpenLLMetryで内部traceを出し、Tracetestでspan assertionを行う構成を示します。

学び: UI/APIテストとtrace検証を結合する具体例として読みます。agentを外から操作するQAと、内部tool/LLM chainの検査を同時に行う型が分かります。

12. Eval設計

Agent Evals Specification: 評価をYAMLで宣言し、レビュー可能にする

Agent Evals仕様は、agent評価をYAMLで宣言し、code judge、LLM judge、rubric、tool trajectory、field accuracy、execution metricsなどを組み合わせる考え方を示します。

学び: trace assertionを理解した後に読むと、個別assertionやjudgeを評価仕様としてどう管理するかが分かります。評価基準をリポジトリでレビュー可能にする発想が中心です。

13. Trace採点

AgentEvals Overview: 実行済みOTel traceを採点する

AgentEvalsは、OpenTelemetry traceやJaeger JSONを読み、agentを再実行せずにtool trajectory、golden eval set、LLM-as-Judgeなどで採点する発想を示します。

学び: 評価仕様の次に読むと、宣言した期待値を実行済みtraceへ当てるイメージが掴めます。LLMの非決定性と再実行コストを避ける設計が中心です。

14. Trace採点

agentevals GitHub: CLIでtraceをCI採点する実装詳細

GitHub READMEは、AgentEvalsをCLIとしてどう動かすか、sample trace、eval set、metrics、CI gate、Web UI、MCP server、対応範囲を具体的に示します。

学び: AgentEvalsの概要を読んだ直後に読む資料です。実際のCI導入、trace file、eval set、metric指定、custom evaluatorの運用が分かります。

15. 実務運用

Hamel Husain LLM Evals FAQ: traceを読んで失敗分類を育てる

このFAQはOpenTelemetry専用ではありませんが、LLM/agent evalを実務で作る手順が非常に具体的です。traceを読み、失敗分類を作り、custom evaluatorへ落とすプロセスを学べます。

学び: ツール群を一通り見た後に読むべき資料です。どのツールを使うかより、何を評価すべきかを実traceから決める方法が分かります。

16. 研究深掘り

Automated Structural Testing論文: trace・mock・assertionでagentをテストする

この論文は、LLM-based agentを最終出力だけで評価するのではなく、OpenTelemetry traceでtrajectoryを取り、mockingで再現性を確保し、assertionで構造的に検査する方法を提案します。

学び: 実務ツールを見た後、自社QA基盤を設計する段階で読む資料です。agentを非決定的な会話相手ではなく、外部依存を持つソフトウェアとしてテストする視点が得られます。

17. 研究深掘り

AgentTelemetry論文: OTel GenAIだけでは見えないagent故障を分類する

AgentTelemetryは、通常のOpenTelemetry GenAI spanだけではplanning、reasoning、guardrail、delegation、memoryに関する故障が見えにくいと主張し、agent-specific span kindとfault taxonomyを提案します。

学び: 最後に読む資料です。標準仕様と既存ツールでどこまででき、どこから独自spanやfault detectorが必要かを判断できます。

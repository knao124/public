読む順番の方針

最初に標準化とtraceの考え方を押さえ、次にinstrumentationでデータを出し、PhoenixやLangWatchで実装像を掴みます。その後、TracetestとAgentEvalsで自動判定の形を学び、最後にHamel Husainの実務FAQと研究論文で評価設計を深める順番です。

短期で試すなら 1 → 2 → 4 → 6 → 13 → 14 を読めば、最小限の実装とCI評価まで到達できます。長期運用まで考えるなら、9、15、16、17を追加してください。

1 全体像 OpenTelemetry AI Agent Observability
解説HTML 原資料
agent observabilityがなぜ必要か、agent applicationとagent frameworkの違い、telemetryを評価ツールへのfeedback loopとして使う考え方が書かれている。 最初に、OTel traceは監視ログではなくagent改善サイクルの共通データ面だと理解できる。vendor lock-inを避ける設計判断の軸も得られる。 最初に読む。以後の資料で出てくるtrace、span、evaluationの位置づけが整理される。
2 標準schema OpenTelemetry GenAI Semantic Conventions
解説HTML 原資料
LLM call、retrieval、tool execution、token、model、provider、tool arguments、tool resultなどをspan属性としてどう表すかが書かれている。 agent QAの評価器が読む最低限のschemaを学べる。どの属性を取らないとwrong tool、invalid arguments、stale retrievalを検査できないかが分かる。 全体像の次。実装や評価ツールを見る前に、共通語彙を押さえる。
3 可視化例 Inside the LLM Call: GenAI Observability with OpenTelemetry
解説HTML 原資料
VS Code Copilotなどのagent interactionをOTelで出し、invoke_agent、chat、execute_toolのspan treeとして見る例が書かれている。 実際のagent実行がどのようなtrace treeに見えるかを掴める。遅延、retry、tool callの原因調査をtraceで行う感覚が得られる。 schemaを読んだ直後。抽象仕様を画面上の実例へ接続する。
4 計測層 OpenInference
解説HTML 原資料

5 計測層 OpenLLMetry / Traceloop
解説HTML 原資料
LLM appをOpenTelemetryで監視・debugするためのOSS instrumentationと、OTLP exporterで既存backendへ送る方法が書かれている。 OpenInference以外の計測選択肢を理解できる。LLM callを通常のobservability pipelineへ載せる実装パターンを学べる。 OpenInferenceと並べて読む。計測ライブラリの比較材料として使う。
6 実装チュートリアル Phoenix Tracing Tutorial
解説HTML 原資料

7 実装チュートリアル Phoenix + Open Agent Spec

8 評価基盤接続 LangWatch OpenTelemetry Integration Guide

9 Simulation QA LangWatch Agent Simulations
解説HTML 原資料
unit test、component eval、agent simulationの3階層と、multi-turn scenarioで中間tool callや状態遷移を検査する方法が書かれている。 agentを単発input-outputではなく、会話・tool・状態を持つprocessとしてテストする方法を学べる。production failureをscenario化する発想が得られる。 OTel接続の後。multi-turn agentやユーザーシミュレーションをQAに入れる段階で読む。
10 Trace assertion Tracetest Docs
解説HTML 原資料

11 Trace assertion Testing LLM Apps with Trace-Based Testing

15 実務運用 Hamel Husain LLM Evals FAQ

16 研究深掘り Automated Structural Testing of LLM-based Agents
解説HTML 原資料
OpenTelemetry traceでagent trajectoryを取り、mockingで再現性を確保し、assertionで自動検証する構造的テスト手法が書かれている。 agent QAをtrace、mock、assertionの3点セットとして設計する方法を学べる。test pyramidやregression testingをagentへ適用する視点が得られる。 実務運用の後。自社で基盤を設計・拡張する段階で読む。
17 研究深掘り AgentTelemetry
解説HTML 原資料
OTel GenAIではplanning、reasoning、guardrail、delegation、memoryが見えにくいという問題と、9 span kind・14 fault typeのtaxonomyが書かれている。 標準spanだけでは検出できないagent故障を学べる。wrong tool、reasoning loop、guardrail bypass、memory corruptionなどを検出するために必要なtelemetry設計が分かる。 最後に読む。標準仕様と既存ツールの限界を理解し、独自spanやfault detectorを設計する材料にする。

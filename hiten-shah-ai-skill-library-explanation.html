Hiten Shah「AI戦略はまずSkill Libraryから」を読む

この記事は、企業の最初のAI戦略を「どのモデルを使うか」「どのコネクタを入れるか」から始めるのではなく、 社内の優秀な人が繰り返している判断・手順・型を Skill Library として蓄積するところから始めるべきだ、 という主張です。

核心は、AI Agentにデータを見せるだけでは仕事の質は上がらない、という点です。Salesforce、Slack、Google Drive、GitHubに接続しても、 「どの情報を重く見るか」「どの例外に注意するか」「何を良いアウトプットとみなすか」は別問題です。そこで著者は、 優秀者の仕事のやり方を、手順・例・テンプレート・チェックリスト・判断基準としてパッケージ化することを提案しています。

主張 企業のAI優位性は、モデル選定そのものよりも、自社の仕事のやり方をAIに教えられるかで決まる。
Skillとは 一回限りのプロンプトではなく、同じ種類の仕事に再利用できる「仕事の進め方」のパッケージ。
Accessとの違い コネクタは文脈を渡す。Skillは判断、手順、品質基準を渡す。
Private Skill 本当に価値があるSkillは、顧客対応、営業基準、法務判断、ブランド文体など、社内固有のものになる。

この記事がそのまま言っている重要フレーズ

“A skill is more than a prompt.”

“Skills make judgment reusable.”

この2つで記事全体の圧縮版になります。つまり、プロンプトはその場の依頼文で、Skillは仕事の型です。そしてSkill Libraryとは、 優秀者の判断を、Agentが何度でも読み込める運用資産にする仕組みです。

記事の中身を段落順に具体化する

動画解説で時刻ごとに追ったのと同じように、ここでは記事の見出し・段落順で内容を追います。各項目は「記事が何を言っているか」と 「その意味」を分けています。

冒頭 優秀な人の仕事には、本人も明文化していない反復パターンがある

著者は、優秀な営業、サポートリード、ファイナンスリーダーの例から始めます。営業なら、重要な商談前に前回の会話、真の意思決定者、 まだ口に出されていない反対理由、数週間前の約束を見に行く。サポートなら、チケット本文だけでなく、顧客の口調、過去の履歴、 アカウント価値、プロダクト上の痛み、小さな問題が大きくなる兆候を見る。ファイナンスなら、数字そのものよりも、どの変化が重要で、 どれがノイズで、取締役会前にどの変化に説明の物語が必要かを読む。

この記事は、この「経験」「判断」「センス」「組織知」と呼ばれてきたものを、AI時代にはSkillとして扱える、と導入しています。

The Work Already Has a Method 仕事にはすでに方法がある。ただし散らばっている

企業には、営業更新準備、顧客フィードバックの優先順位付け、キャンペーン判断、サポートのエスカレーション、危険なコード変更レビュー、 財務変動の読み方など、実はかなり具体的なやり方があります。ただ、その多くはドキュメント、Slack、テンプレート、古い資料、 オンボーディング会話、ベテランの頭の中に分散しています。

著者は、これまで背景知識扱いだったものが、これからはAI Agentのためのインフラになる、と言っています。

Access Is the Easy Part データアクセスは必要だが、それだけでは良い仕事にならない

多くのAI導入はCRM、Slack、Google Drive、GitHub、Data Warehouseへの接続から始まります。著者はこれを否定していません。 むしろ、アクセスできないAgentは推測するだけなので、アクセスは必要だと言っています。

ただしアクセスだけでは、営業メモを全部読めても案件の形を読み違える、サポートチケットを検索できても本当に緊急の顧客を見落とす、 プロダクト資料を全部開けても実際の意思決定に合わないPRDを書く、という失敗が起きます。問題は「見られる情報を増やすこと」ではなく、 「会社がその仕事をどう進めるか」をAgentに理解させることです。

A Skill Is a Reusable Way of Working Skillは、同じ仕事に再適用できる仕事の型

著者は、プロンプトを「その瞬間に何をしてほしいか」、Skillを「繰り返せる仕事のやり方」と分けます。Skillには、手順、例、 テンプレート、チェックリスト、スクリプト、参照資料、経験則が含まれます。

Anthropic型の例としては、SKILL.md と補助ファイルを含むフォルダが挙げられています。重要なのはファイル形式ではなく、 手順だけでなく、判断、例外、品質基準まで入れることです。

具体例 営業準備、事後分析、取締役会資料がSkillになり得る

営業準備Skillなら、アカウント履歴の読み方、表面化すべきリスク、未解決質問の立て方、役に立つ商談ブリーフの形を持ちます。 インシデントポストモーテムSkillなら、時系列復元、原因と症状の分離、非難しない文章化、学びをアクションに落とす方法を持ちます。 取締役会資料Skillなら、どの指標を出すか、変化をどう説明するか、何を付録に逃がすか、どこでストーリーが崩れるかを扱います。

Data, Connectors, Skills, and Plugins Connectorは文脈、Skillは判断、Pluginは行動まで含む方向

記事は、AIシステムの最初の課題をアクセスだと整理します。コネクタ、MCP、API、データ連携は、ドキュメントやDBや業務アプリをAIに見せる。 しかし、Salesforceを見せてもフォーキャストレビューのやり方は教えられません。Driveを接続しても、どの古い取締役会資料を真似し、 どれを無視すべきかは分かりません。

そのうえで、データとコネクタは文脈、Skillは判断とプロセス、Pluginはアクセスとアクションを組み合わせるもの、という進化の流れを置いています。

The Pattern Is Older Than AI 専門性を再利用可能にする流れはAI以前からある

著者は、Unixコマンド、Shell Script、Library、API、Workflowの流れを引きます。人間は昔から、有用な操作、手順、コード、 サービス、業務プロセスを再利用可能にしてきました。AI時代に変わったのは、実行者です。

以前は人がプレイブックを読んで実行していました。今はAgentがプレイブックを読み、ツールを使い、ファイルを調べ、スクリプトを実行し、 継続して作業できます。つまりプレイブックが「読む資料」から「動く運用部品」になります。

The Skill Library Becomes the Asset 同じモデルでも、社内Skill Libraryを持つ会社は別の資産を持つ

同じ最先端モデルを使う2社を比べます。片方は社内システムに接続しただけ。もう片方は、社内システムに接続しつつ、優秀な仕事から作った Skill Libraryも渡している。この後者は、営業準備、契約レビュー、ローンチブリーフ、バグ調査、エスカレーション対応、調査要約、 財務説明のやり方をAgentが知っている状態です。

完璧でも魔法でもないが、十分に一貫性が上がる。良いSkillは同じミスの再修正を減らし、より良いSkillは仕事の最低品質を引き上げ、 最高のSkillは何年もかけて身につく判断を保存する、という位置づけです。

The Best Skills Will Be Private 最も価値のあるSkillは社内固有で、公開マーケットプレイスには出ない

公開Skillマーケットプレイスは便利でも、内容は汎用になりがちです。著者は、価値ある方法は具体的だと言います。顧客エスカレーション手順、 営業の見極め軸、プロダクトレビュー基準、取締役会更新フォーマット、法務の代替条項、ブランド文体、意思決定基準などは、 競合がダウンロードできない社内知です。

Start With the Work 最初にやるべきことは、繰り返し発生する判断作業を棚卸しすること

プラットフォームを選ぶ前に、繰り返し行われる仕事をマップする。特に、経験者が安定して高い成果を出す作業を見る。 例として、営業電話、顧客調査、サポートエスカレーション、PRD、インシデントポストモーテム、契約、予測、ローンチ、競合分析、 リリースノートが挙がっています。

優秀者が最初に何を見るか、他の人は何を見落とすか、どんな良い例・悪い例があるか、何度も聞かれる質問は何か、避けているミスは何か、 成功をどう定義するかを聞き、そこからSkillを作る、という手順です。

The Real AI Strategy 本当のAI戦略は、AIを業務フローの奥に埋め込むこと

企業がAgentから最大の価値を得るには、AIを「汎用知能を社内に振りかけるもの」と見なすのをやめる必要がある、と締めています。 Agentに、自社のビジネスが実際にどう動くかを教える。繰り返される判断を再利用可能なシステムにする。 優秀者の方法を適用しやすく、改善しやすく、失われにくくする。

その意味でAIの優位性は、選んだモデルそのものではなく、モデルにどの仕事をうまくやるよう教えたかから生まれる、というのが最終メッセージです。

Prompt、Connector、Skill、Pluginの違い

Prompt その場の依頼文。例: 「この商談メモを要約して」「このPRDをレビューして」。人間が毎回、背景や判断基準を説明しがち。
Connector / MCP / API Agentが情報源やツールにアクセスするための接続。例: Salesforce、Slack、Google Drive、GitHub、Data Warehouseを見る。
Skill 同じ種類の仕事をどう進めるかをまとめたパッケージ。手順、例、テンプレート、チェックリスト、判断基準、例外、品質基準を含む。
Plugin アクセス、操作、ワークフローを組み合わせた実行単位。記事では、データ接続からSkill、さらに行動できる知的システムへ進む流れとして説明される。

なぜ「毎回プロンプトで説明する」必要が減るのか

Skillなし

人間が毎回、「この会社では何を重要視するか」「この資料はどの順番で見るか」「良いアウトプットは何か」 「この例外はどう扱うか」をプロンプトに書きます。結果として、同じ説明が何度も繰り返され、担当者ごとに品質が揺れます。

Skillあり

Agentが作業前にSkillを読み込みます。そこには、対象データの見方、判断の優先順位、成果物テンプレート、悪い例、確認項目が入っています。 人間は「この商談を準備して」と言うだけで、Agentは社内の型に沿って作業を始められます。

実務でSkill Libraryを作る順番

記事の提案を現場で実行するなら、いきなり巨大なナレッジベースを作るより、判断が繰り返される小さな業務から始めるのが自然です。

繰り返し判断作業を棚卸し 営業準備、顧客調査、PRDレビュー、障害分析、契約レビューなど、経験者ほど品質差が出る業務を選ぶ。
優秀者の見方を抽出 最初に見る情報、見落としやすい兆候、良い例、悪い例、避けている失敗、成功条件を聞く。
Skillとしてパッケージ化 手順、入力、出力テンプレート、判断基準、例外、品質チェック、参照資料を1つのフォルダや文書にまとめる。
使って改善する Agentの失敗例をSkillに戻し、現場に近い人をownerにして、古くなった判断基準を更新する。

この記事の主張をSkillに落とすとこうなる

たとえば営業商談準備をSkill化するなら、単に「商談準備して」とは書かず、次のような再利用可能な型にします。 

# Sales Call Prep Skill

Use when preparing for an important customer or prospect call.

Inputs:
- CRM account record
- Previous meeting notes
- Open opportunities
- Support and product issue history

Process:
1. Identify the real buyer, economic buyer, and likely blockers.
2. Compare last stated goals with the current opportunity stage.
3. Surface unstated objections or risk signals from notes and support history.
4. Pull promises or follow-ups from the last 30 days.
5. Produce a brief with risks, open questions, next best move, and talk track.

Quality bar:
- Do not summarize everything.
- Prioritize information that changes the call strategy.
- Call out uncertainty instead of inventing missing context.

ここで重要なのは、Agentに「全部読んで要約して」と言わないことです。何を探すべきか、何を捨てるべきか、どの水準なら使える準備資料なのかを Skill側に持たせます。

この記事が想定しているSkill Libraryの具体例

Support Escalation Skill 顧客の口調、契約規模、過去障害、プロダクト上の痛み、炎上兆候を見て、単なる返信ではなく優先度と対応方針を決める。
Incident Postmortem Skill タイムラインを復元し、原因と症状を分け、誰かを責める文章を避け、再発防止を具体的なアクションに落とす。
Board Deck Skill どの指標を本文に置き、どの詳細を付録に置き、どの変化に説明が必要で、どこでストーリーが破綻するかを判断する。
Product Review Skill 顧客要望を重要度、再現性、戦略整合性、既存ロードマップへの影響で見て、単なる人気投票にしない。
Contract Review Skill 標準条項、許容できる代替案、交渉してよい範囲、絶対に譲れない条件をAgentに読み込ませる。
Brand Voice Skill ブランド文体、避ける表現、顧客に刺さる言い回し、過去の良いコピー例をまとめ、生成文の一貫性を上げる。

読み取りポイント

AI戦略の起点が変わる

「どのモデルが一番賢いか」だけを比較しても、社内業務の質は自動では上がりません。この記事は、モデルよりも モデルに渡す社内の仕事の型 を資産として見るべきだと主張しています。

Skill LibraryはAgent用の運用マニュアル

人間向けマニュアルは読まれないことがありますが、Agentは作業前にSkillを読み込んで実行できます。だから、古いドキュメントやSlackスレッドの 断片を、実際に使われる作業単位へ変換する価値が出ます。

価値は社内固有知にある

汎用Skillは誰でも使えます。本当に差が出るのは、顧客、商品、法務、営業、サポート、ブランド、意思決定基準など、 会社ごとに違う暗黙知をSkill化した部分です。

Skillは作って終わりではない

判断基準が古くなると、Agentは古い会社のやり方を忠実に再現します。現場に近いownerを置き、失敗例や新しい成功例を更新する運用が必要です。

注意点

  • 優秀者の型を保存するだけでなく、古い慣習や悪い癖を固定化していないかを確認する必要があります。
  • 社内固有Skillには営業基準、法務ポジション、顧客情報、ブランド戦略が含まれ得ます。アクセス権限と保管場所はコネクタ以上に慎重に扱うべきです。
  • Skillは再利用のための型ですが、すべてのケースに同じ型を当てると判断を誤ります。例外条件と「人間に戻す条件」を明記するのが重要です。
  • Skill Libraryはナレッジ整理ではなく業務改善の道具です。再修正の減少、初稿品質、対応時間、判断の一貫性など、運用指標と結びつける必要があります。

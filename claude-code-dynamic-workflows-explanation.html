Claude Code Docs / Dynamic workflows

Claude Code の Dynamic workflows は「大量のサブエージェント運用をコード化する仕組み」

生成日時: 2026-06-03 09:31 JST / 対象: https://code.claude.com/docs/en/workflows

このページは、Claude Code で多数のサブエージェントを使う作業を、Claude が書く JavaScript の ワークフロースクリプトとして実行・監視・再利用する方法を説明している。狙いは「1 回の会話で順番に頼む」から、 「計画、分岐、集約、検証をスクリプトに持たせて背景実行する」へ移すこと。

いつ使うか 大規模調査、全体監査、数百ファイル規模の移行、複数視点での計画レビュー。
何が違うか オーケストレーションが Claude の会話ではなく、実行されるスクリプトに入る。
注意点 多くのエージェントを起動するので、通常の会話よりトークンと時間を使う。

読む前の前提

ここでの「ワークフロー」は、一般的な CI/CD の YAML ではなく、Claude Code がタスクに応じて生成する JavaScript の制御スクリプトを指す。スクリプト自体はファイル操作やシェル実行を直接行わず、サブエージェントを起動し、 それぞれの結果を変数として保持しながら次の段階へ進める。

利用条件: ドキュメント上では research preview 扱い。Claude Code v2.1.154 以降が必要で、有料プラン、Anthropic API、 Amazon Bedrock、Google Cloud Vertex AI、Microsoft Foundry で利用できる。Pro では /config の Dynamic workflows 行から有効化する。
  • 単位: 1 つのワークフロー実行。内部に複数フェーズと多数のエージェントを持てる。
  • 実行者: ランタイムがスクリプトをバックグラウンド実行し、各作業はサブエージェントが担当する。
  • 成果物: 最終レポート、変更計画、監査結果、保存された再利用コマンドなど。

中核の考え方

Dynamic workflows の価値は、単に「並列にたくさん呼べる」ことではなく、作業の進め方を再実行可能なコードに落とせる点にある。 たとえば、複数エージェントが別々に調査し、別エージェントが矛盾をチェックし、生き残った主張だけを最終レポートにまとめる、 という品質パターンを毎回同じ形で走らせられる。

会話型の委任との違い: サブエージェントやスキルでは、次に何をするかを Claude がターンごとに判断する。ワークフローでは、ループ、分岐、 中間結果の保持、再試行の構造がスクリプト側にある。

サブエージェント、スキル、Agent teams との使い分け

選択肢 計画を持つ場所 向いている規模 繰り返しやすいもの
サブエージェント Claude の会話コンテキスト 数個の独立タスク ワーカー定義
スキル Claude が従う手順書 決まった作業手順 手順とルール
Agent teams リードエージェント 少数の長時間ピア作業 チーム構成
Dynamic workflows ランタイムが実行するスクリプト 数十から数百のエージェント オーケストレーションそのもの

判断基準は「たくさん動かすか」だけではなく、「中間結果を会話コンテキストではなくコードの変数として扱いたいか」。

まず試すなら /deep-research

Claude Code には、調査用の組み込みワークフローとして /deep-research がある。質問を渡すと、複数の角度で Web 検索し、ソースを取得し、主張を照合して、引用付きのレポートを返す。途中のエージェント作業は背景で進む。 

/deep-research What changed in the Node.js permission model between v20 and v22?
1 実行

質問を付けてコマンドを入力する。

2 承認

計画と実行許可を確認する。

3 監視

/workflows でフェーズとエージェントを追う。

4 詳細確認

各エージェントのプロンプト、ツール呼び出し、結果を見る。

5 レポート

照合済みの主張だけを含む最終結果を読む。

自分のタスク用ワークフローを書かせる

単発で使いたい場合は、プロンプトで「workflow を使って」「run a workflow」などと頼むか、 ultracode: を付ける。Claude は通常のターン進行ではなく、タスク用のワークフロースクリプトを生成して実行する。 

ultracode: audit every API endpoint under src/routes/ for missing auth checks

セッション全体で Claude に判断させたい場合は /effort ultracode を使う。これは高い推論努力と自動ワークフロー化を 組み合わせる設定なので、通常作業よりトークンも時間も重くなる。

実務上の目安: 毎回必要なわけではない。1 ディレクトリだけの修正や明確な単発バグなら、普通の会話やサブエージェントで十分なことが多い。

承認と権限のポイント

CLI では実行前に、フェーズ計画を見て実行、今後同じワークフローを自動承認、スクリプト表示、キャンセルを選べる。 Desktop app では、ワークフロー名、フェーズ、トークン使用への注意を含む承認カードが出る。

  • ワークフローが起動するサブエージェントは acceptEdits モードで動き、ツール allowlist を継承する。
  • ファイル編集は自動承認される。
  • allowlist にないシェル、Web fetch、MCP ツールは途中で確認を求めることがある。
  • 長時間実行する前に、必要なコマンドを allowlist に入れておくと止まりにくい。

うまくいった実行はコマンドとして保存できる

/workflows で実行を選び、s を押すと、その実行のスクリプトを保存できる。保存先は プロジェクト共有の .claude/workflows/ か、自分専用の ~/.claude/workflows/。 保存後は / として呼び出せる。

保存済みワークフローには args として入力を渡せる。たとえば issue 番号のリストや対象パスを渡し、 スクリプト側では構造化データとして扱える。

実行モデルと制限

ワークフローランタイムは、会話とは別の隔離環境でスクリプトを実行する。中間結果は Claude の会話コンテキストではなく、 スクリプト変数やランタイムの管理情報として扱われる。実行スクリプトはセッション配下の ~/.claude/projects/ に書かれ、必要なら読んだり差分確認したりできる。

  • 実行中のユーザー入力は不可
  • スクリプト自体は FS / shell に直接アクセスしない
  • 同時実行は最大 16 エージェント
  • 1 実行あたり最大 1,000 エージェント
  • 停止後の再開は同じセッション内で有効

コスト管理

ワークフローは多数のエージェントを起動するため、通常の会話より利用量が大きくなりやすい。大きなタスクをいきなり全体に かけるのではなく、まず狭い範囲で試すのが安全。/workflows ではフェーズやエージェントごとのトークン使用を確認でき、 途中停止もできる。

おすすめの始め方: 「全 repo」ではなく「1 ディレクトリ」、「幅広い調査」ではなく「絞った問い」で試し、結果の品質と使用量を見てから広げる。

使わない場合の無効化

Dynamic workflows は CLI、Desktop app、IDE extensions、claude -p、Agent SDK で使える。無効化するには /config の Dynamic workflows をオフにする、~/.claude/settings.json に "disableWorkflows": true を設定する、または CLAUDE_CODE_DISABLE_WORKFLOWS=1 を使う。 組織全体では managed settings や管理画面から無効化できる。

実務での読み方

この機能は「常に最上位の作業モード」ではなく、大規模な並列性、再利用可能な検証パターン、背景実行、再開性が必要なときの 選択肢として読むのがよい。特に監査、移行、調査のように、同じ問いを多面から見て、結果を突き合わせるタスクで効く。

逆に、ユーザーの途中判断が何度も必要な作業、コストを厳密に抑えたい作業、局所的で明確な修正には過剰になりやすい。

静的HTMLをさっと public 化するなら何が一番いいか

前提が「HTML 内の情報は公開してよい」「S3 や IAM 的な管理は重い」「local で見えているものを他人にもすぐ見せたい」なら、 いちばん筋が良い既定解は Netlify Drop です。

最有力: Netlify Drop 瞬間共有: TryCloudflare Git前提: GitHub Pages

結論

常用の既定解としては Netlify Drop を勧めます。ローカルの public / dist / build フォルダを そのままドラッグして数秒で *.netlify.app の URL が出るので、 「local では見えるが、良いものを人に見せるときだけ公開したい」という用途に最も素直です。

ただし、もし「アップロードすらしたくない。今このローカルサーバーをそのまま誰かに見せたい」なら、 TryCloudflare のようなトンネルの方がさらに軽いです。代わりに、 これは継続公開向きではなく、テストやデモ向きです。

使い分け早見表

手段 向いている場面 良い点 注意点
Netlify Drop ローカルの静的 HTML 一式をそのまま公開したい ドラッグ&ドロップだけで公開、更新も同じ操作でよい index.html をルートに置くのが基本。ブラウザ経由の大きなアップロードは不向き
TryCloudflare その場で一時的に共有、デモ、レビュー デプロイ不要。ローカルサーバーを即 public URL 化 Cloudflare 公式に「testing/development only」。PC を止めると見えなくなる
GitHub Pages HTML を GitHub に置いていて、更新履歴も Git で持ちたい 単純、安定、github.io URL がすぐ使える push 前提。単発の共有にはやや一手間
Cloudflare Pages Direct Upload ドラッグ&ドロップで継続公開したい、将来 custom domain も視野 *.pages.dev で公開、ローカル資産のアップロードが可能 Direct Upload プロジェクトは後から Git integration に切り替え不可

一番おすすめ: Netlify Drop

Netlify の公式ドキュメントは、Netlify Drop を「ローカルのフォルダにある Web project を最速で公開する方法」と位置づけています。 フォルダを drop zone に置くだけで netlify.app の共有 URL が払い出され、 更新時も新しいフォルダをもう一度ドラッグすれば差し替えられます。

向いている理由

  • public フォルダをそのまま投げられる
  • viewer 側の認証管理が要らない
  • 単発公開にも継続公開にも使いやすい

実運用の感覚

  • 公開 URL が安定していて、人に送りやすい
  • ローカル PC を起動し続ける必要がない
  • S3 のようなバケット設定を考えなくてよい
1. 公開したい HTML/CSS/JS 一式を 1 フォルダにまとめる
2. ルートに index.html があることを確認する
3. https://app.netlify.com/drop にドラッグ
4. 出てきた *.netlify.app を共有する

CLI 派なら netlify deploy --allow-anonymous で live URL を出す方法もあります。 これは一時的な匿名 deploy で、1 時間以内に claim しないと消えます。

もっと軽い一時共有: TryCloudflare

すでにローカルで HTML を見せられているなら、トンネル系は「その状態を public URL に変換する」だけです。 Cloudflare の Quick Tunnels は cloudflared tunnel --url http://localhost:8080 で起動でき、 ランダムな trycloudflare.com の URL を返します。 

python3 -m http.server 8080
cloudflared tunnel --url http://localhost:8080

これは最短ですが、Cloudflare 自身が testing / development 用と明記しています。 継続公開の本番置き場にはしない方がよいです。

Git が前提なら GitHub Pages

GitHub Pages は、GitHub 上の repository にある HTML / CSS / JS をそのまま静的サイトとして公開する仕組みです。 repository の branch と folder を Pages の公開元に選ぶだけでよく、URL も https://<owner>.github.io または https://<owner>.github.io/<repository> になります。

すでに GitHub に載せているものを公開するならかなり素直ですが、 「できたものをその場でポンと公開したい」用途では Drop 系より一手多いです。

Cloudflare Pages Direct Upload はどうか

これも drag and drop で静的ファイルを公開できるので悪くありません。 ただし公式ドキュメントには、Direct Upload を選ぶと後から Git integration に切り替えられないこと、 dashboard の drag and drop では functions フォルダをコンパイルしないことが明記されています。

なので「Cloudflare を強く使いたい理由がある」なら候補ですが、 プレーンな静的 HTML を手早く見せるだけなら、まずは Netlify Drop の方が素直です。

実務向けの判断

普段の既定解

Netlify Drop。迷ったらこれでよいです。

5分だけ見せたい

TryCloudflare。アップロードすら不要です。

Git で残したい

GitHub Pages。push と公開を一体化できます。
